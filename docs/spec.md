# Spec: スーパーボリンジャー トレード支援エージェント (FX Trade Agent)

本仕様書は、為替取引（FX）および株式市場におけるテクニカル指標「スーパーボリンジャー」を活用したシグナル検知・バックテスト可視化ダッシュボードの**製品要求仕様書 (PRD) / 開発指示書 / スペック駆動開発のガイドライン**である。
他のAIエージェントや開発者が本仕様書をインプットとするだけで、寸分違わぬ機能・UI・描画ハックを備えたアプリケーションを完全再現できる粒度で記述されている。

---

## 1. Objective (システム目的)
為替取引（FX）の代表的な指標「スーパーボリンジャー」を活用し、ドル円（USD/JPY）の各時間軸および米国個別株（GOOG）の売買シグナル判定、リアルタイム評価損益のトラッキング、バックテスト（シミュレーション）結果を統合表示する高機能ダッシュボードを構築する。

プロフェッショナルなFX取引ツール（TradingView等）と同等の高精度なチャート描画、相場特性に合わせた時間軸別特化ロジックの厳格な適用、日本の投資慣習に合わせた視覚設計、および放置監視を可能にする完全自動リフレッシュインフラを統合したプロダクトを提供する。

## 4. Detailed Technical Specifications (詳細仕様)

### 4.1 データ取得と時間軸のクレンジング (`data_fetcher.py`)

#### A. データ取得範囲と期間およびタイムアウト (最重要)
*   **API接続の堅牢化 (タイムアウトの明示)**:
    `yfinance` を用いたすべての HTTP ダウンロード (`yf.download`) 時には、必ず **`timeout=30` (秒)** を指定し、APIサーバーのハング時にスレッドが無限に待ち状態となることを防止する。
*   **ドル円 (USD/JPY, `JPY=X`)**:
    - 1時間足 (`1h`): 過去2年分 (`2y`)
    - 日足 (`1d`): 過去5年分 (`5y`)
*   **Google個別株 (GOOG) / その他の個別アセット**:
    - 日足 (`1d`): 過去5年分 (`5y`)
*   **個別アセットの条件分岐処理**:
    - `symbol` が為替 `"JPY=X"` 以外のときは、不要な1時間足データ（1h）のダウンロードや4時間足へのリサンプル処理をスキップし、日足（`1d`）のみを取得してクリーンアップして返す。
*   **データギャップの排除**:
    - 土日や祝日など取引がない期間のデータ（NaN行）は、単純に `dropna` で削除し、時系列の間隔を詰めて連番インデックスで管理可能にする。

#### B. 為替日足のスマート補正ハック
- **背景**: yFinanceから取得する為替（USD/JPY）の日足データは、インターバンク市場の特性上、始値と終値がほぼ同一価格になり、実体が極端に潰れた「十字線」ばかりになってしまい、ローソク足チャートとしての視認性を著しく損なう。
- **解決策**: 為替（`JPY=X`）の1日足に対してのみ、以下の「始終値スマート補正」を強制適用する。
  1. **終値のフォワードロール**: 「当日の終値 (`Close`)」を「**翌日の始値 (`Open`)**」の値で上書きする（最後の1行のみ、自身の元の `Close` を維持）。
  2. **高安値のセーフティ調整**: 終値の書き換えによって `High` または `Low` の範囲外に飛び出すことを防ぐため、以下の論理値調整を適用する。
     - $High_{new} = \max(High_{old}, Close_{new})$
     - $Low_{new} = \min(Low_{old}, Close_{new})$
  3. ※株式データ（`GOOG`）など、為替以外のシンボルにはこの補正は**絶対に適用してはならない**。

#### C. 4時間足（4H）のリサンプリング
- 為替（`JPY=X`）にのみ適用し、1時間足（`1h`）のデータからPandasのリサンプルを用いて生成する。
- リサンプル定義: `df_1h.resample('4h', closed='left', label='left', origin='start_day')`
- 集計方法（OHLCVマッピング）:
  - Open: `first`
  - High: `max`
  - Low: `min`
  - Close: `last`
  - Volume: `sum` (為替は基本0となる)
- リサンプル後にデータが存在しない（NaN）行は `dropna` で完全に排除する。

## 4.2 スーパーボリンジャーの算出定義 (`indicator.py`)

N＝21期間を基本とする。母標準偏差（`ddof=0`）を使用して以下の指標および評価フラグを算出する。

1.  **センターライン (21SMA)**: 21期間の単純移動平均線 (`center_line` および互換キー `21MA`)。
    $$center\_line_t = \frac{1}{21}\sum_{i=0}^{20} Close_{t-i}$$
2.  **ボリンジャーバンド (±1σ, ±2σ, ±3σ)**:
    $$std_t = \sqrt{\frac{1}{21}\sum_{i=0}^{20} (Close_{t-i} - center\_line_t)^2}$$
    $$plus\_k\sigma_t = center\_line_t + (std_t \times k) \quad (k \in \{1, 2, 3\})$$
    $$minus\_k\sigma_t = center\_line_t - (std_t \times k) \quad (k \in \{1, 2, 3\})$$
    *(※検証ツール側との完全互換性を確保するため、`+1σ`, `+2σ`, `-1σ`, `-2σ` などのギリシャ文字キー名も同時に定義しデータフレームに追加する)*
3.  **描画用遅行スパン (`chikou_span`)**: 当日の終値を **21期間過去（左方向）** にシフトした時系列。
    $$chikou\_span_{t-21} = Close_t \quad (df['Close'].shift(-21))$$
4.  **シグナル判定用高安補助列 (`past_high_21`, `past_low_21`, `past_close_21`)**:
    現在の終値と21期間前の物理ローソク足との比較を行うため、過去21本前の高値・安値・終値を**現在行（右方向）**へシフトした補助列を作成する（検証ツール用の `High_21_ago` 等も同一）。
    $$past\_high\_21_t = High_{t-21} \quad (df['High'].shift(21))$$
    $$past\_low\_21_t = Low_{t-21} \quad (df['Low'].shift(21))$$
5.  **エクスパンション状態、および境界判定フラグ**:
    - バンド幅拡大判定 (`Expansion`): $+2\sigma$ が前日比で上昇 かつ $-2\sigma$ が前日比で下降。
    - 終値境界フラグ: 終値が各バンド（$\pm 1\sigma, \pm 2\sigma$、およびセンターライン）を上抜けているか下抜けているかの評価フラグ（`Close_gt_plus1`, `Close_lt_21MA` 等）をすべてベクトル計算でデータフレームに事前付与する。

#### 4.2.1 MACD指標の算出定義
モジュール化のため、MACD指標は独立した関数 `calculate_macd(df, fast=12, slow=26, signal=9)` にて算出する。
1. **MACD線 (`macd`)**: 12期間の指数移動平均(EMA) - 26期間のEMA
2. **シグナル線 (`macd_signal`)**: MACD線の9期間のEMA
3. **ヒストグラム (`macd_hist`)**: MACD線 - シグナル線
4. **ゴールデンクロス (`macd_gc`)**: 当日のMACD > シグナル、かつ前日のMACD <= シグナル
5. **デッドクロス (`macd_dc`)**: 当日のMACD < シグナル、かつ前日のMACD >= シグナル

## 4.3 売買ロジックと共通シミュレーションエンジン (`backtest.py`)

#### A. バンド幅エクスパンション (Expansion) の定義
ボラティリティの拡大を厳密に捉えるため、以下の論理AND条件を満たす状態をエクスパンションとする。
- $$Expansion_t = (plus\_2\sigma_t > plus\_2\sigma_{t-1}) \land (minus\_2\sigma_t < minus\_2\sigma_{t-1})$$

#### B. 約定ルール（翌足始値約定・厳密モデル）
- エントリーまたは決済条件がバー `t` の終値確定時点で満たされた場合、取引は約定遅延を考慮し、**必ず次のバー `t+1` の始値 (`Open`)** で約定したものとして資産残高を計算する。

#### C. 21MA同方向エントリーフィルター (重要)
- 決済条件に21MA（センターライン）を含む戦略（`EX3, EX5, EX6, EX7`）を実行する場合、レンジ相場でのねじれ往復ビンタ（細かな連敗）を排除するため、エントリー時に以下のフィルターを強制適用する。
  - **買いエントリー時**: 価格が21MAより上であること ($Close_t > center\_line_t$)
  - **売りエントリー時**: 価格が21MAより下であること ($Close_t < center\_line_t$)

#### D. 各時間軸・アセットの売買ロジック割り当て
*   **ロング（買い）エントリー条件 (遅行スパン好転 ＆ 条件)**:
    - `lagging_type` が `high_low` の場合: $Close_t > past\_high\_21_t$
    - `lagging_type` が `close` の場合: $Close_t > past\_close\_21_t$
    - 指定されたエントリー戦略（E1〜E6）のバンドブレイクおよびエクスパンションを満たした場合に発火。
*   **ショート（売り）エントリー条件 (遅行スパン逆転 ＆ 条件)**:
    - `lagging_type` が `high_low` の場合: $Close_t < past\_low\_21_t$
    - `lagging_type` が `close` の場合: $Close_t < past\_close\_21_t$
    - 指定されたエントリー戦略（E1〜E6）のバンドブレイクおよびエクスパンションを満たした場合に発火。

*   **決済（エグジット）条件 (EX1〜EX7)**:
    - EX1: 遅行スパン陰転（買い） / 陽転（売り）
    - EX2: 終値が $\pm 1\sigma$ を内側に割り込む（買いなら $< +1\sigma$、売りなら $> -1\sigma$）
    - EX3: 終値が 21MA センターラインを割り込む（買いなら $< 21MA$、売りなら $> 21MA$）
    - EX4〜EX7: 上記の組み合わせ（OR条件）

#### E. 汎用エンジン (`run_backtest`) のインターフェース
検証グリッドサーチとUIダッシュボードの双方から呼び出される共通の関数シグニチャ：
```python
def run_backtest(df: pd.DataFrame, entry_strat: str = None, exit_strat: str = None, lagging_type: str = None, timeframe: str = None, volume: int = 10000, initial_capital: float = 1000000.0, lot_size: int = None) -> dict
```
- UI側の後方互換性を保つため、`timeframe` パラメータが指定された場合は、内部で対応する戦略の組み合わせに自動的にマッピング解決する。
  - `timeframe="1h_macd_doten"` の場合、MACD のゴールデンクロス (`macd_gc == True`) でドテン買いエントリー、デッドクロス (`macd_dc == True`) でドテン売りエントリーを行う。
- 戻り値には、現在のポジション情報、取引履歴 (`trades`)、プロット用の残高推移（`balance_history` DataFrame形式）、および検証スクリプト用の `metrics` 辞書を含めて返す。

## 4.4 チャート描画と Plotly ハック仕様 (`components/charts.py`)

TradingViewと同等の等間隔で美しいチャート描画を実現するため、以下の独自の Plotly ハックを完全実装する。

1.  **X軸の等間隔カテゴリ軸化 (休場ギャップ排除)**:
    Datetime を文字列リスト（例: `['05-22 08:00', ...]`）に変換し、Plotlyの軸設定で `type='category'` を指定することで取引のない期間の空白を詰めて描画する。
2.  **不可視文字を活用した一意性確保ハック (必須)**:
    Plotlyでカテゴリ軸を使用した際、X軸の文字列に重複（年跨ぎ等での日付重複）があると描画順序が崩壊するため、データの最初の行の年からの経過年数分だけ末尾にゼロ幅スペース（不可視文字: `\u200b`）を付加し、表示は同一でありながら内部で一意に識別できるようにする。
3.  **最新64足の初期表示ウィンドウ制御とY軸動的オートスケール**:
    - 初期表示範囲: Plotlyの `xaxis_range` を `[len(df) - 64.5, len(df) - 0.5]` に設定し、直近の最新64足を初期表示とする。
    - Y軸のオートスケール: 表示範囲（最新64足）のデータ内から、有効な `High`, `Low`, `plus_3sigma`, `minus_3sigma`, `chikou_span` の最大値と最小値を動的に抽出し、上下5%のマージンを加算した値を `yaxis_range` に適用する。
4.  **操作性制限**: 凡例は非表示。ドラッグ操作は「横スクロール移動」に固定し、ズームは無効化する (`dragmode='pan'`)。
5.  **MACDドテンチャート (`create_macd_chart`)**:
    - Plotlyの `make_subplots` を使用して、上段にローソク足チャートとドテン売買シグナルマーカー、下段に MACD線、シグナル線、およびヒストグラム（プラス値は赤 `#ef5350`、マイナス値は青 `#42a5f5`）を配置した2段構成のチャート。
    - 上下段でX軸を共有し（`shared_xaxes=True`）、ズームや移動が連動するように制御。カテゴリ軸化およびその他の表示仕様はスーパーボリンジャーチャートと同一。

## 4.5 Streamlit UI/UX レイアウトと自動更新 (`app.py`)

#### A. 画面構成とグリッドデザイン
- **為替セクション (USD/JPY)**:
  - 画面上部に `2 x 2` の4グリッドを構成する。
  - 左上: 総合サマリーコンテナ（時間軸・ロジック別のステータスバッジ、成績表）。
  - 右上: 1時間足（1H）スーパーボリンジャーチャート / 左下: 1時間足（1H）MACDドテン売買チャート / 右下: 日足（1D）スーパーボリンジャーチャート。
- **米国株セクション (GOOG)**:
  - 為替の下段に、横幅いっぱいの独立したコンテナを配置。
  - 左側1/3に「GOOG 日足サマリー」、右側2/3に「GOOG 日足チャート」を配置する。

#### B. 総合サマリー表示のビジュアル設計
- 各時間軸のステータス表示は、StreamlitのMarkdownを用いて美しくデザインされたバッジ形式で出力する。
- ポジションバッジ: 買いは 🟢 (`#00e676`背景)、売りは 🔴 (`#ff5252`背景)、ノーポジは ⚪ (`#424242`背景)。
- ポジション保有時は、バッジの右側にインデントを開けて「建値: X円 ➔ 評価損益: +Y円」と表示する。
- **適用戦略の階層的表示 (必須要件)**:
  - 各時間軸のシグナルバッジの**直下の行**に、1段インデント（`↳` 矢印記号付き、文字色 `#b0bec5` の薄いグレー、サイズ `0.85em`）を下げて、「↳ エントリー」「↳ エグジッド」に分けて定義テキストを記載する。
  - **1時間足 (1H) スーパーボリンジャー**:
    - `↳ エントリー: 遅行スパン陽転 & バンド拡大 & ±2σ 越え`
    - `↳ エグジッド: ±1σ割れ`
  - **1時間足 (1H) MACD**:
    - `↳ エントリー: MACDゴールデンクロス (買いドテン)`
    - `↳ エグジッド: MACDデッドクロス (売りドテン)`
  - **日足 (1D)**:
    - `↳ エントリー: 遅行スパン陽転 & ±1σ 越え`
    - `↳ エグジッド: 遅行スパン陰転 or 21MA割れ`

#### C. st.fragment による自動更新インフラ (必須)
- **全体リロードコードの廃止**:
  JavaScriptによる不安定なブラウザリロード（CORS制限によるエラーやタブ休止によるフリーズ）は**完全に廃止**する。
- **Python側での自律Fragmentリフレッシュ**:
  データのダウンロードからPlotlyチャートの描画までの一連のブロックを `render_dashboard()` 関数内に配置し、デコレータ **`@st.fragment(run_every=3600)`** を付与する。
  これにより、ブラウザ全体の再読み込みを発生させずに、1時間ごとにPython側で最新データを再取得し、画面（WebSocket通信）をサイレント更新する。

## 5. Spec-Driven Development (スペック駆動開発) 指行ルール

本リポジトリにおける開発・保守を行うすべての開発者およびAIエージェントは、本仕様書に基づいた**スペック駆動開発（SDD）**を徹底しなければならない。

### 5.1 開発プロセスと行動規範
1.  **仕様ファーストの徹底**:
    - コードを変更・拡張（新規エントリー条件の追加、決済ルールの調整など）する前に、**必ず最初に `docs/spec.md` の対応セクションを更新・編集**し、新しい仕様を定義すること。
    - 仕様書を更新し、ユーザーの承認を得るまでは、本番およびテストのソースコードを1行たりとも書き換えてはならない。
2.  **ソース・オブ・トゥルース（信頼できる唯一の情報源）の遵守**:
    - `docs/spec.md` に記載された数式、約定ルール、パラメータ、ビジュアル要件は「絶対的な正義」である。ソースコードの実装は常にこの仕様書と一言一句一致しなければならない。
3.  **変更後の回帰テスト要件**:
    - コード変更後は、必ず以下のテストを実行し、エラーが発生しないこと、およびUSD/JPY・GOOGのテスト取引成績に意図しないズレが生じていないことを保証すること。
      - `./venv/bin/python src/components/backtest/run_all_tests.py`
      - `./venv/bin/python goog_backtest.py`
      - `./venv/bin/python test_backtest_run.py`

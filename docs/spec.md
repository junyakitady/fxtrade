# Spec: スーパーボリンジャー トレード支援エージェント (FX Trade Agent)

本仕様書は、為替取引（FX）および株式市場におけるテクニカル指標「スーパーボリンジャー」を活用したシグナル検知・バックテスト可視化ダッシュボードの**製品要求仕様書 (PRD) / 開発指示書**である。
他のAIエージェントや開発者が本仕様書をインプットとするだけで、寸分違わぬ機能・UI・描画ハックを備えたアプリケーションを完全再現できる粒度で記述されている。

---

## 1. Objective (システム目的)
為替取引（FX）の代表的な指標「スーパーボリンジャー」を活用し、ドル円（USD/JPY）の各時間軸および米国個別株（GOOG）の売買シグナル判定、リアルタイム評価損益のトラッキング、バックテスト（シミュレーション）結果を統合表示する高機能ダッシュボードを構築する。

プロフェッショナルなFX取引ツール（TradingView等）と同等の高精度なチャート描画、相場特性に合わせた時間軸別特化ロジックの厳格な適用、日本の投資慣習に合わせた視覚設計、および放置監視を可能にする完全自動リロードインフラを統合したプロダクトを提供する。

## 4. Detailed Technical Specifications (詳細仕様)

### 4.1 データ取得と時間軸のクレンジング (`data_fetcher.py`)

#### A. データ取得範囲と期間
- **ドル円 (USD/JPY, `JPY=X`)**:
  - 1時間足 (`1h`): 過去730日分（yFinanceの1時間足ダウンロード限界期間）。
  - 日足 (`1d`): 過去5年分。
- **Google個別株 (GOOG)**:
  - 日足 (`1d`): 過去5年分。
- **データギャップの排除 (必須)**:
  - 土日や祝日など取引がない期間のデータ（NaN行）は、単純に `dropna` で削除し、時系列の間隔を詰めて連番インデックスで管理可能にする。

#### B. 為替日足のスマート補正ハック (必須)
- **背景**: yFinanceから取得する為替（USD/JPY）の日足データは、インターバンク市場の特性上、始値と終値がほぼ同一価格になり、実体が極端に潰れた「十字線」ばかりになってしまい、ローソク足チャートとしての視認性を著しく損なう。
- **解決策**: 為替（`JPY=X`）の1日足に対してのみ、以下の「始終値スマート補正」を強制適用する。
  1. **終値のフォワードロール**: 「当日の終値 (`Close`)」を「**翌日の始値 (`Open`)**」の値で上書きする（最後の1行のみ、自身の元の `Close` を維持）。
  2. **高安値のセーフティ調整**: 終値の書き換えによって `High` または `Low` の範囲外に飛び出すことを防ぐため、以下の論理値調整を適用する。
     - $High_{new} = \max(High_{old}, Close_{new})$
     - $Low_{new} = \min(Low_{old}, Close_{new})$
  3. ※株式データ（`GOOG`）は始値終値のボラティリティが正常なため、この補正は**絶対に適用してはならない**。

#### C. 4時間足（4H）のリサンプリング
- 1時間足（`1h`）のデータからPandasのリサンプルを用いて生成する。
- リサンプル定義: `df_1h.resample('4h', closed='left', label='left', origin='start_day')`
- 集計方法（OHLCVマッピング）:
  - Open: `first`
  - High: `max`
  - Low: `min`
  - Close: `last`
  - Volume: `sum` (為替は基本0となる)
- リサンプル後にデータが存在しない（NaN）行は `dropna` で完全に排除する。

### 4.2 スーパーボリンジャーの算出定義 (`indicator.py`)

N＝21期間を基本とする。母標準偏差（`ddof=0`）を使用して以下の指標を算出する。

1.  **センターライン (21SMA)**: 21期間の単純移動平均線。
    $$center\_line_t = \frac{1}{21}\sum_{i=0}^{20} Close_{t-i}$$
2.  **ボリンジャーバンド (±1σ, ±2σ, ±3σ)**:
    $$std_t = \sqrt{\frac{1}{21}\sum_{i=0}^{20} (Close_{t-i} - center\_line_t)^2}$$
    $$plus\_k\sigma_t = center\_line_t + (std_t \times k) \quad (k \in \{1, 2, 3\})$$
    $$minus\_k\sigma_t = center\_line_t - (std_t \times k) \quad (k \in \{1, 2, 3\})$$
3.  **描画用遅行スパン (`chikou_span`)**: 当日の終値を **21期間過去（左方向）** にシフトした時系列。
    $$chikou\_span_{t-21} = Close_t$$
    *(※Pandasの実装では `df['Close'].shift(-21)`。これは描画専用であり、後述のシグナル判定には用いない)*
4.  **シグナル判定用高安補助列 (`past_high_21`, `past_low_21`) (最重要)**:
    ボリンジャーバンドの本来の遅行スパン解釈である**「現在の終値と21期間前の物理ローソク足の高値・安値とのピンポイントクロス」**をベクトル演算で高速処理するため、過去21本前の高値・安値を**現在行（右方向）**へシフトした補助列を作成する。
    $$past\_high\_21_t = High_{t-21} \quad (df['High'].shift(21))$$
    $$past\_low\_21_t = Low_{t-21} \quad (df['Low'].shift(21))$$

### 4.3 売買ロジック (マルチ・ロジック / HIGH_LOW 基準) (`backtest.py`)

すべての時間軸において、遅行スパンのクロス判定は**高安値基準 (HIGH_LOW)** を採用する。
ポジションはロング（買い）/ショート（売り）両対応、同時に最大1ポジションのみ保有（単利運用、ドテンなし）。既存ポジション保有中は他のエントリーシグナルを完全に無視する。

#### A. バンド幅エクスパンション (Expansion) の定義 (共通必須要件)
ボラティリティの拡大を厳密に捉えるため、以下の論理AND条件を満たす状態をエクスパンションとする。
- **+2σの上昇**: 当日の $+2\sigma$ が前日より大きい ($\Delta plus\_2\sigma > 0$)
- **-2σの下降**: 当日の $-2\sigma$ が前日より小さい ($\Delta minus\_2\sigma < 0$)
- $$Expansion_t = (plus\_2\sigma_t > plus\_2\sigma_{t-1}) \land (minus\_2\sigma_t < minus\_2\sigma_{t-1})$$

#### B. 各時間軸・アセットの売買ルール詳細

##### 1. 【為替 1時間足 (1h) ／ 4時間足 (4h) ／ GOOG 日足】
強いトレンドの初動のみを捉え、勢いが衰えたら即撤退する「+2σエクスパンション厳選＆スピード決済モデル」。
- **ロング（買い）エントリー (全3AND)**:
  - 遅行スパン陽転: 当日終値が21日前高値を上回る ($Close_t > past\_high\_21_t$)
  - ボラティリティ拡大: $Expansion_t$ が真
  - 終値基準クリア: 当日終値が $+2\sigma$ を上回る ($Close_t > plus\_2\sigma_t$)
- **ロング決済 (EX1)**:
  - 遅行スパン陰転: 当日終値が21日前安値を下回る ($Close_t < past\_low\_21_t$)
- **ショート（売り）エントリー (全3AND)**:
  - 遅行スパン陰転: 当日終値が21日前安値を下回る ($Close_t < past\_low\_21_t$)
  - ボラティリティ拡大: $Expansion_t$ が真
  - 終値基準クリア: 当日終値が $-2\sigma$ を下回る ($Close_t < minus\_2\sigma_t$)
- **ショート決済 (EX1)**:
  - 遅行スパン陽転: 当日終値が21日前高値を上回る ($Close_t > past\_high\_21_t$)

##### 2. 【為替 日足 (1d)】
日足のトレンドを深く追いかけつつ、ドローダウンを抑える「1σ厳選＆ダブルセーフティ決済モデル」。
- **ロング（買い）エントリー (全3AND)**:
  - 遅行スパン陽転: $Close_t > past\_high\_21_t$
  - ボラティリティ拡大: $Expansion_t$ が真
  - 終値基準クリア: 当日終値が $+1\sigma$ を上回る ($Close_t > plus\_1\sigma_t$)
- **ロング決済 (EX5 - OR条件)**:
  - 遅行スパン陰転 ($Close_t < past\_low\_21_t$) **または** 終値が21MAセンターラインを割り込む ($Close_t < center\_line_t$)
- **ショート（売り）エントリー (全3AND)**:
  - 遅行スパン陰転: $Close_t < past\_low\_21_t$
  - ボラティリティ拡大: $Expansion_t$ が真
  - 終値基準クリア: 当日終値が $-1\sigma$ を下回る ($Close_t < minus\_1\sigma_t$)
- **ショート決済 (EX5 - OR条件)**:
  - 遅行スパン陽転 ($Close_t > past\_high\_21_t$) **または** 終値が21MAセンターラインを超える ($Close_t > center\_line_t$)

### 4.4 シミュレーションエンジンとメトリクス算出仕様 (`backtest.py`)

#### A. 実行シグニチャと入出力
```python
def run_backtest(df: pd.DataFrame, timeframe: str = "1h", volume: int = 10000, initial_capital: float = 1000000) -> dict
```
- **ロットサイズ**: 為替 (`1h`, `4h`, `1d`) は `volume=10000` (1万通貨固定)、米国株 (`GOOG`) は `volume=100` (100株固定)。
- **入力データフレーム**: `indicator.py` にて指標算出済みのもの。
- **データフレームの拡張 (動的カラム付与)**:
  - `signal`: 売買トリガー（`1`: 買入, `2`: 買出, `-1`: 売入, `-2`: 売出, `0`: シグナルなし）を記録。
  - `position`: そのバー終了時点の保有ポジション（`1`: ロング, `-1`: ショート, `0`: ノーポジ）。
  - `trade_profit`: ポジション決済が実行されたバーに、そのトレードの確定損益を記録。
  - `cumulative_profit`: 累積損益の推移。

#### B. シミュレーションアルゴリズム (イベントループ)
1. インジケータ算出に必要な最小期間（`21MA`, `past_high_21` が NaN でない最初のインデックス、実質インデックス21）からループを開始する。
2. **約定価格仕様 (重要)**:
   - バー `t` でエントリー/エグジットの条件を満たした場合、**次のバー `t+1` の始値 (`Open`)** で約定したものとして売買処理を行う。
   - トレード損益（実現損益）の計算式:
     - ロング時: $Profit = (ExitPrice - EntryPrice) \times Volume$
     - ショート時: $Profit = (EntryPrice - ExitPrice) \times Volume$
3. **強制決済ルール (バックテスト統計集計用)**:
   - ループがデータフレームの最終行（現在時刻）に達した時点でポジションを保有していた場合、**最終行の終値 (`Close`)** で強制的にクローズしたものと仮定し、過去の合計損益や勝率などの統計集計値にその損益を含める。
   - ※注意: これはバックテストの最終結果を確定させるための統計上の処理であり、実際のリアルタイム運用においてポジションが現在時刻や週末跨ぎで強制決済されるものではありません。リアルタイムで保有中のポジションはそのまま維持され、週明けの市場再開後も建値を引き継いで評価損益が推移します。
4. **リアルタイム評価損益（未実現損益）の算出 (アプリUI連携)**:
   - 現在も保有中のポジションがある場合の評価損益は、最新の終値を用いて動的に計算して返す。
   - $UnrealizedProfit = (LatestClose - EntryPrice) \times Volume \times CurrentPosition$

#### C. パフォーマンスメトリクスの算出式
- **勝率 (Win Rate)**:
  $$WinRate (\%) = \frac{WinTrades}{TotalTrades} \times 100$$
- **プロフィットファクター (Profit Factor)**:
  $$ProfitFactor = \frac{\sum (Profit > 0)}{\sum |Profit < 0|}$$
  *(※負けトレードがない (分母=0) かつ勝ちがある場合は `float('inf')`、取引自体がない場合は `0.0`)*
- **最大ドローダウン (Max Drawdown)**:
  - 各トレード時点ではなく、データフレームの行ごと（毎日/毎時間）の資産残高ベースで計算する。
  - $Equity_t = InitialCapital + CumulativeProfit_t$
  - $Peak_t = \max_{i=0..t}(Equity_i)$
  - $Drawdown_t = Peak_t - Equity_t$
  - 金額ベース最大DD: $MaxDD_{Amount} = \max(Drawdown_t)$
  - パーセントベース最大DD: $MaxDD_{Percent} = \max\left(\frac{Drawdown_t}{Peak_t}\right) \times 100$

### 4.5 チャート描画と Plotly ハック仕様 (`components/charts.py`)

TradingViewと同等の等間隔で美しいチャート描画を実現するため、以下の独自の Plotly ハックを完全実装する。

#### 1. X軸の等間隔カテゴリ軸化 (休場ギャップ排除)
- **課題**: 時系列 (`DatetimeIndex`) をそのままX軸にマッピングすると、土日や夜間の取引がない期間に不自然な空白（ギャップ）が生じ、チャートが間延びする。
- **解決策**: Datetime を文字列リスト（例: `['05-22 08:00', '05-22 09:00', ...]`）に変換し、Plotlyの軸設定で `type='category'` を指定する。これにより、データが存在する行のみが等間隔でプロットされる。

#### 2. 不可視文字を活用した一意性確保ハック (必須)
- **課題**: `type='category'` を指定した際、X軸の文字列に「重複」があると、Plotlyは同一の軸カテゴリとみなしてしまい、描画順序が崩壊する（過去のデータが現在の位置に重なって描画されるバグ）。
- **解決策**:
  1. データフレームの最初の行の年を `base_year` とする。
  2. 各行のインデックスに対して、`(idx.year - base_year)` の数だけ、末尾にゼロ幅スペース（不可視文字: `\u200b`）を付加する。
  3. これにより、表示上は同一の `'05-22 08:00'` でありながら、異なる年であればユニークな文字列となり、Plotly内部で一意に識別されて描画崩壊を完全に防止できる。

#### 3. 最新64足の初期表示ウィンドウ制御とY軸動的オートスケール
- **初期表示範囲**: チャートロード時の初期状態では、最も直近の動向が見やすい**最新の64足**の範囲を初期表示とする。
  - Plotlyの `xaxis_range` を `[len(df) - 64.5, len(df) - 0.5]` に設定する。
- **Y軸のオートスケール (最重要)**:
  - ユーザーがスクロールする前の初期表示において、ローソク足がY軸いっぱいに美しく表示されるよう、表示範囲（最新64足）のデータのみからY軸レンジを動的に算出する。
  - 表示範囲内の `High`, `Low`, `plus_3sigma`, `minus_3sigma`, `chikou_span` の全系列から有効値（NaNを除く）の最大値 ($Max$) と最小値 ($Min$) を取得する。
  - 余白マージンとして上下に5%のクッションを加算する。
    - $y\_pad = (Max - Min) \times 0.05$
    - $Y軸表示レンジ = [Min - y\_pad, Max + y\_pad]$
  - この値を `yaxis_range` に適用してチャートを描画する。

#### 4. チャート配色・スタイルガイドライン (完全指定)
- **ローソク足**: 日本の業界慣習に準拠。陽線＝赤 (`#ef5350`)、陰線＝青/水色 (`#42a5f5`)。
- **スーパーボリンジャー各種バンド**:
  - センターライン (21MA): 薄いグレー (`#e0e0e0`)、実線
  - ±1σ: 薄いグレー/点線 (`#b0bec5`, dash='dot', opacity=0.4)
  - ±2σ: ピンク/細い実線 (`#f48fb1`, width=1.2, opacity=0.7)
  - ±3σ: 赤/細い実線 (`#ef9a9a`, width=1.2, opacity=0.7)
- **遅行スパン**: 紫/やや太い実線 (`#b388ff`, width=1.8)
- **シグナルマーカー (売買サイン)**:
  - マーカーの描画位置インデックスの抽出には、必ず `np.where(df['signal'] == code)[0]` を用いて純粋な位置配列を取得する。
  - 買いエントリー (`signal == 1`): 緑色の上向き矢印マーカー (`#00e676`, symbol='triangle-up', size=12)。ローソク足の `Low` の少し下に配置。
  - 買いエグジット (`signal == 2`): オレンジ色の下向き矢印マーカー (`#ff9100`, symbol='triangle-down', size=12)。ローソク足の `High` の少し上に配置。
  - 売りエントリー (`signal == -1`): 紫色の下向き矢印マーカー (`#ea80fc`, symbol='triangle-down', size=12)。ローソク足 of `High` の少し上に配置。
  - 売りエグジット (`signal == -2`): シアン色（水色）の上向き矢印マーカー (`#18ffff`, symbol='triangle-up', size=12)。ローソク足の `Low` の少し下に配置。
- **操作性制限**: 凡例は非表示 (`showlegend=False`)。誤操作による表示ブレを防ぐため、ドラッグ操作は「横スクロール移動」に固定し、ズームは無効化する (`dragmode='pan'`)。

  - ノーポジション: ⚪ダークグレーのバッジ (`#424242`背景)
- **建値と評価損益の表示 (ポジション保有時のみ)**:
  - ポジションバッジの右側に、インデントを開けて小さめの文字で「建値: X円 ➔ 評価損益: +Y円」と表示する。評価損益はプラスなら緑、マイナスなら薄赤色でリアルタイムの数値を強調表示する。
- **適用戦略の階層的表示 (最重要ビジュアル要件)**:
  - 各時間軸のシグナルバッジの**直下の行**に、1段インデント（`↳` 矢印記号付き、文字色 `#b0bec5` の薄いグレー、サイズ `0.85em`）を下げて、適用されている売買ロジックの定義テキストを記載する。
  - **1時間足 / 4時間足**: `↳ 戦略: 入: 遅行スパン陽転 & エクスパンション & 終値 > +2σ | 出: 遅行スパン陰転`
  - **日足**: `↳ 戦略: 入: 遅行スパン陽転 & エクスパンション & 終値 > +1σ | 出: 21MA割れ`
- **データテーブルサマリー**:
  - バッジ表示の下に、3つの時間軸の成績（シグナル判定、総取引回数、勝率、損益合計）をまとめた Pandas データフレームを `st.dataframe(hide_index=True, width='stretch')` で表示する。
  - ※データテーブル内は文字幅を確保するため、上記の長い「戦略列」は**必ず除外**しておくこと。

### 4.7 常時モニタリングインフラと自動化 (`app.py`)

- **キャッシュの全面禁止**:
  - 常に最新のマーケットデータを反映し、ポジションステータスや評価損益の狂いをゼロにするため、Streamlitのデータキャッシュデコレータ（`@st.cache_data`, `@st.cache_resource`）は**一切使用してはならない**。
- **1時間自動フルリロードJSハック (必須)**:
  - ディスプレイでの常時監視（放置運用）に対応するため、1時間（3600秒）が経過した時点で、ブラウザ全体をサイレントに自動リロードする JavaScript を非表示コンテナで埋め込む。
  - さらに、ユーザーがタブをバックグラウンドからフォアグラウンド（アクティブ）に切り替えた際にも、前回のロードから1時間以上経過していれば、その瞬間に即座にページを強制リロードするイベントリスナーを仕込む。

```python
# app.py に埋め込む自動リロードJSコンポーネントの実装仕様
st.html(
    """
    <script>
        const lastLoadTime = Date.now();
        const refreshInterval = 3600000; // 1時間 (ミリ秒)

        // 1. タブがアクティブになった瞬間の時間経過判定リロード
        document.addEventListener("visibilitychange", function() {
            if (document.visibilityState === "visible") {
                const elapsed = Date.now() - lastLoadTime;
                if (elapsed >= refreshInterval) {
                    window.parent.location.reload();
                }
            }
        });

        // 2. 開きっぱなしの状態での1時間タイマーリロード
        setTimeout(function(){
            window.parent.location.reload();
        }, refreshInterval);
    </script>
    """
)
```

## 5. Development Boundary & QA Constraints (開発境界と品質条件)

- **絶対に守るべきこと (Always)**:
  - 遅行スパンの判定基準はすべて **`HIGH_LOW` 基準 (21日前のローソク足高安値との比較)** で統一すること。
  - チャートの等間隔カテゴリ軸表示と、年跨ぎでのX軸重複を防ぐ `\u200b` 不可視文字ハックを実装すること。
  - Y軸レンジは、最新64足の描画オブジェクトから上下5%のマージンを考慮して動的計算すること。
  - 為替日足データの「翌日始値の終値へのロール補正」を適用し、株式には適用しないこと。
- **事前に相談すること (Ask First)**:
  - スーパーボリンジャーの期間（N=21）や算出方法を変更する場合。
  - 取引数量（1万通貨 / 100株）や初期資金の設定を変更する場合。
- **絶対にやってはならないこと (Never)**:
  - Streamlitのデータキャッシュを適用して、古いシグナルや約定価格のズレを発生させること。
  - TradingView等のプロツールと比べて、時系列の土日ギャップ（空白行）の放置によるチャートの間延びを許容すること。
  - 物理的な過去高安ブレイク判定（BREAKOUT基準）をロジックに混ぜ、ボリンジャーバンドの本来の性質から乖離させること。

このPRDは、本システムの唯一の「ソース・オブ・トゥルース（信頼できる唯一の情報源）」であり、すべてのモジュールはこの仕様に厳格に従ってコーディングされなければならない。

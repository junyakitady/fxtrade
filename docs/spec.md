# Spec: スーパーボリンジャー トレード支援エージェント (FX Trade Agent)

## 1. Objective
為替取引（FX）の代表的なテクニカル指標「スーパーボリンジャー」を活用し、ドル円（USD/JPY）および米国個別株（GOOG）の売買シグナル判定とシミュレーション結果を統合表示するダッシュボードアプリケーションを構築する。
単なる指標計算にとどまらず、**TradingView等のプロ仕様ツールと同等の直感的な操作性、アセット特性別の特化型ロジック適用、日本の慣習に合わせた配色、および常時自動モニタリング可能なインフラ**を備えることを最終目標とする。

## 2. Tech Stack
- **言語**: Python 3.11+
- **環境構築**: `venv` + `uv`
- **データ取得**: `yfinance` (Yahoo Finance API)
- **数値処理**: `pandas`, `numpy`
- **UIフレームワーク**: `streamlit`
- **可視化・チャート**: `plotly`

## 5. Detailed Specifications

### 5.1 データ取得と時間軸のクレンジング
- **対象ペアと期間**: 
  - 為替 `USD/JPY` (`JPY=X`): 1時間足は過去730日分、日足は過去5年分。
  - 米国株 `GOOG`: 日足のみ過去5年分。
- **為替日足のスマート補正ハック (必須要件)**:
  - 為替データの提供元仕様により、日足の始値と終値がほぼ同値になり実体が潰れる（十字線ばかりになる）問題が存在する。
  - 解決策として、`df_1d_clean` に対して **「当日の終値 (`Close`) を、翌日の始値 (`Open`) で置き換える」** 処理（`np.roll` を活用）を適用する。さらに描画矛盾を防ぐため `High` と `Low` も補正後 `Close` を包含するように再調整する。
  - ※株式データ (`GOOG`) は始値終値のボラティリティが正常なため、この置き換え補正は**適用しない**。
- **4時間足の生成**: 1時間足データからのリサンプリング (`resample('4h')`) によって生成。
- **休場処理**: 全アセットにおいて、週末や祝日等のデータが存在しない行は削除し、ギャップを詰める。

### 5.2 スーパーボリンジャーの算出定義
- **基本期間 (N)**: 21期間
- **センターライン**: 21期間単純移動平均線 (21SMA)
- **ボリンジャーバンド**: センターライン ± 1σ, ± 2σ, ± 3σ (母標準偏差 `ddof=0` を使用)
- **遅行スパン**: 当日の終値を **21期間過去** にシフトした線
- **補助列の追加**: ベクトル演算判定用として、過去21本前の高値・安値を現在へシフトした列 (`past_high_21`, `past_low_21`) を付与する。

### 5.3 売買ロジック (マルチ・ロジック戦略)
全探索シミュレーションによって厳選された、アセットや時間軸固有のボラティリティ特性に合わせた特化型モデルを個別に適用する。ポジションは最大1つ（単利運用）、ドテンなし。

#### 1. 【為替 1h ／ 米国株 GOOG 日足】: +2σエクスパンション厳選モデル
モメンタム特性が強いアセットやノイズが多い足に対し、本物のブレイクアウト初動のみを捉えるモデル。
- **買いエントリー (全3AND)**: 遅行スパン好転 ＆ 終値 > **+2σ** ＆ バンド拡大 (-2σ下向き)
- **買い決済**: 遅行スパン逆転のみ
- **売りエントリー (全3AND)**: 遅行スパン逆転 ＆ 終値 < **-2σ** ＆ バンド拡大 (+2σ上向き)
- **売り決済**: 遅行スパン好転のみ

#### 2. 【為替 4h】: 1σウォーク＆スピード撤退モデル
- **買いエントリー (全2AND)**: 遅行スパン好転 ＆ 終値 > **+1σ**
- **買い決済**: 終値 < **+1σ** のみ
- **売りエントリー (全2AND)**: 遅行スパン逆転 ＆ 終値 < **-1σ**
- **売り決済**: 終値 > **-1σ** のみ

#### 3. 【為替 1d】: 特大ホームラン特化モデル
- **買いエントリー (全3AND)**: 遅行スパン好転 ＆ 終値 > **+1σ** ＆ バンド拡大 (-2σ下向き)
- **買い決済**: 終値 < **センターライン(21SMA)** のみ
- **売りエントリー (全3AND)**: 遅行スパン逆転 ＆ 終値 < **-1σ** ＆ バンド拡大 (+2σ上向き)
- **売り決済**: 終値 > **センターライン(21SMA)** のみ

### 5.4 バックテスト・シミュレーションエンジンの詳細仕様
- **インターフェース**: `run_backtest(df: pd.DataFrame, timeframe: str = "1h", volume: int = 10000) -> dict`
  - ※GOOG呼び出し時は `volume=100` (100株固定) とし、`timeframe="1h"` を渡すことで+2σ厳選モデルを適用する。
- **シミュレーション機構**: 単一ポジションのイベント駆動ループ（行ごとの逐次処理）。保有中のポジション状態 (`current_position` = `1`, `-1`, `0`) を追跡し、保有中は他のエントリー条件を完全にスキップする。
- **データ構造の動的拡張**: 入力データフレームをコピーし、戻り値に `signal` (1:買入, 2:買出, -1:売入, -2:売出)、`position`、`trade_profit`、`cumulative_profit` 列を付与する。
- **出力集計値**: 総取引回数、買いトレード数、売りトレード数、勝率、総損益合計。

### 5.5 UI/UXおよびチャートの詳細設計 (完全再現要件)

#### 1. レイアウトとセクション構成
- **為替セクション**: 画面上段に `2 x 2` グリッドを配置（左上: 総合サマリー、右上: 1h、左下: 4h、右下: 1d）。
- **米国株セクション**: 為替の下段に横長のコンテナを独立して設け、左側にGOOGステータスと成績、右側に日足チャートを配置する。
- **サマリー表示**: 表（データテーブル）側からは戦略列を省いて横幅を確保し、**「各バッジアイコンの直下の行に、インデントを揃えて適用戦略を記載する」** 階層的なデザインを義務付ける。

#### 2. X軸の等間隔カテゴリ軸化 (休場ギャップ排除)
- 日時インデックスをあらかじめ文字列リストに変換し、Plotlyのレイアウトで `xaxis=dict(type='category')` を明示する。

#### 3. 不可視文字を活用した重複回避ハック (必須要件)
- 1時間足等のラベルを `MM-DD hh:mm` 形式とした場合、長期データにおいて去年の同月日・時刻との文字列重複による描画崩壊を防ぐため、**「基準年からの年の差分だけ、末尾にゼロ幅スペース (`\u200b`) を付与する」** 処理を施す。

#### 4. 初期表示の限定とY軸の動的オートスケール
- ロード時はローソク足が見やすい**最新の64足**を初期X軸レンジとする。
- その64足の期間内に描画されている主要要素（ローソク足高値・安値、±3σバンド、遅行スパン）の最大値・最小値を算出し、**上下5%の余白を加えたレンジを初期Y軸に設定する。**

#### 5. 配色および操作オプション
- **日本の慣習色**: 陽線＝赤 (`#ef5350`)、陰線＝青 (`#42a5f5`)。
- **マーカー表現**: 買い入＝緑↑ (`#00e676`)、買い出＝オレンジ↓ (`#ff9100`)、売り入＝紫↓ (`#ea80fc`)、売り出＝シアン↑ (`#18ffff`)。
- **操作性**: 凡例非表示 (`showlegend=False`)、ドラッグ操作を横スクロール移動 (`dragmode='pan'`) に固定。
- **安全な位置抽出**: マーカー描画点抽出には、必ず `np.where(df['signal'] == code)[0]` を用いて純粋なNumpy位置配列を取得すること。

### 5.6 自動化および監視要件
- **自動リロード**: Streamlitの `components.html` を用いて、**1時間ごとにブラウザ全体を自動リロードするJS**を非表示で埋め込む。
- **キャッシュの禁止**: 古い状態を残さないため、Streamlitの `@st.cache_data` デコレータは使用しない（または解除する）。

## 6. Code Style
```python
# 例: data_fetcher.py における為替日足の実体補正ハックの標準実装
import numpy as np
import pandas as pd

def correct_daily_candles(df: pd.DataFrame) -> pd.DataFrame:
    """当日の終値を翌日の始値で補正し、実体の潰れを防ぐ。"""
    if not df.empty and len(df) > 1:
        close_arr = np.roll(df["Open"].to_numpy(), -1)
        close_arr[-1] = df["Close"].iloc[-1]
        df["Close"] = close_arr
        # 描画の矛盾を防ぐセーフティ調整
        df["High"] = np.maximum(df["High"], df["Close"])
        df["Low"] = np.minimum(df["Low"], df["Close"])
    return df

# 例: charts.py における不可視文字ハックとNumpy位置抽出
def format_unique_x_strings(df: pd.DataFrame) -> list[str]:
    x_strings = []
    base_year = df.index[0].year
    for idx in df.index:
        base_str = idx.strftime('%m-%d %H:%M')
        unique_str = base_str + ('\u200b' * (idx.year - base_year))
        x_strings.append(unique_str)
    return x_strings

def get_safe_indices(df: pd.DataFrame, signal_code: int) -> np.ndarray:
    return np.where(df['signal'] == signal_code)[0]
```

## 7. Testing Strategy
- **データ精度のテスト**: 置き換えハック後の日足 `Close` と翌日 `Open` の一致確認。
- **シグナル重畳のテスト**: `np.where` によって抽出されたシグナルカウントとFigure内のTraces数が合致すること。
- **自動リロードのテスト**: バックグラウンドのJSタイマーによって定期的かつ静かにページ全体がリフレッシュされること。

## 8. Boundaries
- **Always**: ロジックの厳格な関数分離、位置インデックス抽出による安全な描画。
- **Ask First**: インジケーターのパラメータ変更、UI上の新たな表示列の追加。
- **Never**: Streamlitキャッシュの安易な有効化による計算状態の不整合、表示上のデータギャップの放置。

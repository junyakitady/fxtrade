# Spec: スーパーボリンジャー トレード支援エージェント (FX Trade Agent)

## 1. Objective
為替取引（FX）の代表的なテクニカル指標「スーパーボリンジャー」を活用し、ドル円（USD/JPY）の売買シグナル検知およびシミュレーション結果を統合表示するダッシュボードアプリケーションを構築する。
単なる指標計算にとどまらず、**TradingView等のプロ仕様ツールと同等の直感的な操作性、日本の慣習に合わせた美しいチャート表現、および常時自動モニタリング可能な堅牢性**を備えることを最終目標とする。

## 2. Tech Stack
- **言語**: Python 3.11+
- **環境構築**: `venv` + `uv`
- **データ取得**: `yfinance` (Yahoo Finance API)
- **数値処理**: `pandas`, `numpy`
- **UIフレームワーク**: `streamlit`
- **可視化・チャート**: `plotly`

## 5. Detailed Specifications

### 5.1 データ取得と時間軸のクレンジング
- **対象ペア**: `USD/JPY` (`JPY=X`)
- **データ保持期間**: 各時間軸のチャート上で**確実に1000本以上のローソク足を保持**させるため、取得期間を以下のように最大化する。
  - 1時間足 (1h): 過去730日分（`yfinance` の上限値）
  - 日足 (1d): 過去5年分
  - 4時間足 (4h): 1時間足データから `resample('4h')` で集約して生成
- **ギャップ詰め処理**: 週末や祝日等の休場によりデータが存在しない（または欠損値の）行は完全に削除し、時間的ギャップを詰めて連続したデータとして指標を算出する。

### 5.2 スーパーボリンジャーの算出定義
- **基本期間 (N)**: 21期間
- **センターライン**: 21期間単純移動平均線 (21SMA)
- **ボリンジャーバンド**: センターライン ± 1σ, ± 2σ, ± 3σ (母標準偏差 `ddof=0` を使用)
- **遅行スパン**: 当日の終値を **21期間過去** にシフトした線
- **シグナル判定用補助列**: 当日行でのベクトル演算判定を可能にするため、過去21本前の高値・安値を現在へシフトした列 (`past_high_21`, `past_low_21`) を追加する。

### 5.3 売買ロジック (マルチ・ロジック戦略: 時間軸別・平均利益トップモデル)
ポジションは最大1つ（単利運用）。ドテンは行わず、ノーポジション時にのみエントリーを判定する。
全探索シミュレーションによって抽出された、各時間軸の相場特性に合わせた最強設定を個別に適用する。

#### 【1時間足 (1h)】: +2σエクスパンション厳選モデル
- **買いエントリー (全3AND)**: 遅行スパン好転 ＆ 終値 > **+2σ** ＆ バンド拡大 (-2σ下向き)
- **買い決済**: 遅行スパン逆転のみ
- **売りエントリー (全3AND)**: 遅行スパン逆転 ＆ 終値 < **-2σ** ＆ バンド拡大 (+2σ上向き)
- **売り決済**: 遅行スパン好転のみ

#### 【4時間足 (4h)】: 1σウォーク＆スピード撤退モデル
- **買いエントリー (全2AND)**: 遅行スパン好転 ＆ 終値 > **+1σ**
- **買い決済**: 終値 < **+1σ** のみ
- **売りエントリー (全2AND)**: 遅行スパン逆転 ＆ 終値 < **-1σ**
- **売り決済**: 終値 > **-1σ** のみ

#### 【日足 (1d)】: 特大ホームラン特化モデル
- **買いエントリー (全3AND)**: 遅行スパン好転 ＆ 終値 > **+1σ** ＆ バンド拡大 (-2σ下向き)
- **買い決済**: 終値 < **センターライン(21SMA)** のみ
- **売りエントリー (全3AND)**: 遅行スパン逆転 ＆ 終値 < **-1σ** ＆ バンド拡大 (+2σ上向き)
- **売り決済**: 終値 > **センターライン(21SMA)** のみ

### 5.4 バックテスト・シミュレーションエンジンの詳細仕様
- **インターフェース**: `run_backtest(df: pd.DataFrame, timeframe: str = "1h", volume: int = 10000) -> dict`
  - 時間軸コード (`timeframe`) を受け取り、内部の判定ロジックを自動切り替えする。
- **シミュレーション機構**: 単一ポジションのイベント駆動ループ（行ごとの逐次処理）。保有中のポジション状態 (`current_position` = `1` (Long), `-1` (Short), `0` (None)) を追跡し、ポジション保有中は他のエントリー条件を完全にスキップする。
- **データ構造の動的拡張**: 入力データフレームをコピーし、以下の分析用列を追加して戻り値 (`df_result`) とする。
  - `signal`: シグナルコード (`1`: 買いエントリー, `2`: 買い決済, `-1`: 売りエントリー, `-2`: 売り決済)
  - `position`: 当該行でのポジション状態 (`1`, `-1`, `0`)
  - `trade_profit`: 当該行で確定した個別のトレード損益
  - `cumulative_profit`: 当該行時点での累積損益（資産推移可視化用）
- **取引履歴の追跡 (`trades`)**: 各トレードの種別 (`type`: `LONG`/`SHORT`)、エントリー日時・価格、決済日時・価格、および確定純損益をリスト内に辞書形式で蓄積する。
- **取引量とコスト**: 1回あたり1万通貨固定。スプレッド・手数料はなし。
- **出力集計値**: 総取引回数、買いトレード数 (`long_trades`)、売りトレード数 (`short_trades`)、勝率、総損益合計。

### 5.5 UI/UXおよびチャートの詳細設計 (重要・完全再現要件)

#### 1. X軸の等間隔カテゴリ軸化 (休場ギャップの排除)
- 日時インデックスをそのまま渡すと休場の期間が空白になるため、あらかじめフォーマット済みの文字列リストに変換し、Plotlyのレイアウトで `xaxis=dict(type='category')` を明示する。

#### 2. 不可視文字を活用した重複回避ハック
- 1時間足等のラベルを `MM-DD hh:mm` 形式とした場合、長期データにおいて去年の同月日・時刻と文字列が重複し、Plotlyの描画が崩壊する。
- これを防ぐため、**「基準年からの年の差分だけ、末尾にゼロ幅スペース (`\u200b`) を付与する」** 処理を行い、表示上の見た目を変えずに完全な文字列の一意性を確保する。

#### 3. 初期表示の限定とY軸の動的オートスケール
- チャートロード時は、ローソク足の形状が最も見やすい**最新の64足**を初期X軸レンジとしてフォーカスする。
- さらに、その64足の期間内に描画されている主要要素（ローソク足高値・安値、±3σバンド、遅行スパン）の最大値・最小値を算出し、**上下5%の余白を加えたレンジを初期Y軸に設定する。**
- ※古いデータは、ユーザーがドラッグやスクロールを行うことで自由に閲覧可能。

#### 4. 配色および操作オプション
- **日本の慣習に合わせたローソク足**: 陽線＝赤 (`#ef5350`)、陰線＝青 (`#42a5f5`)。
- **バンド領域**: ±1σ〜±3σの間を透過色（緑、青、紫の微弱な透過領域）で階層的に塗りつぶし。
- **マーカー表現**: 
  - 買いエントリー: 緑の `triangle-up` (`#00e676`)
  - 買い決済: オレンジの `triangle-down` (`#ff9100`)
  - 売りエントリー: 紫の `triangle-down` (`#ea80fc`)
  - 売り決済: シアンの `triangle-up` (`#18ffff`)
- **操作性**: 凡例非表示 (`showlegend=False`) により描画領域を最大化。ドラッグ操作を横スクロール移動 (`dragmode='pan'`) に固定。

#### 5. インデックス不整合対策 (抽出義務)
- 決済マーカー等の描画点を抽出する際は、Pandasのフィルタリングによるインデックスズレを防ぐため、必ず `np.where(df['signal'] == code)[0]` を用いて純粋なNumpy位置インデックス配列を取得すること。

### 5.6 自動化および監視要件
- **自動リロード**: Streamlitの `components.html` を用いて、**1時間（3,600,000ms）ごとにブラウザ全体を自動リロードするJavaScript**を非表示で埋め込む。
- **キャッシュの禁止**: コード変更時の反映漏れや毎時の最新データ取得を阻害する要因となるため、Streamlitの `@st.cache_data` デコレータは使用しない（または無効化する）。

## 6. Code Style
```python
# 例: charts.py における不可視文字ハックとNumpy抽出の標準実装
import numpy as np
import pandas as pd

def format_unique_x_strings(df: pd.DataFrame) -> list[str]:
    """見た目を変えずに文字列の一意性を担保する。"""
    x_strings = []
    base_year = df.index[0].year
    for idx in df.index:
        base_str = idx.strftime('%m-%d %H:%M')
        unique_str = base_str + ('\u200b' * (idx.year - base_year))
        x_strings.append(unique_str)
    return x_strings

def get_safe_indices(df: pd.DataFrame, signal_code: int) -> np.ndarray:
    """Pandasのインデックス不整合を回避して安全に整数位置を取得する。"""
    return np.where(df['signal'] == signal_code)[0]
```

## 7. Testing Strategy
- **データ精度のテスト**: 休場排除後のShape縮小確認、および遅行スパン算出値と補助列の整合性チェック。
- **シグナル重畳のテスト**: `np.where` によって抽出されたエントリーと決済のカウント数が合致し、Figure内に全マーカーのTracesが正しく生成されること。
- **自動リロードのテスト**: ダッシュボード起動後、バックグラウンドのJSタイマーによって定期的かつ静かにページがリフレッシュされること。

## 8. Boundaries
- **Always**: ロジックの厳格な関数分離、位置インデックス抽出による安全な描画。
- **Ask First**: インジケーターのパラメータ変更、UI上の新たな表示列の追加。
- **Never**: Streamlitキャッシュの安易な有効化による計算状態の不整合、表示上のデータギャップの放置。
